# 영상·콘텐츠 플랫폼 수집 정책

뉴유니버스 nu-browser-use 데이터 수집 인프라의 수집 범위와 금지선. 검증일: 2026-08-18.

## 원칙

1. **원문 비보관** — 수집 대상은 Derived Annotation(메타데이터, 집계 지표, 홍보 에셋)만. 원문 저작물(에피소드 영상, 대본 전문)은 보관하지 않는다.
2. **무인증·공개 경로만** — 브라우저가 익명 방문자로서 받는 것과 동일한 데이터만. 로그인 우회, 앱 전용 API 역설계, 서명/토큰 위조는 접근통제 회피에 해당하며 금지.
3. **연결 품질 > 수집량** — 전수보다 재현 가능한 파이프라인.
4. **배포 2단계, NAS가 기록의 원본** — C: 로컬 → NAS `X:\nu-browser-use\<name>_export`(WSL `/mnt/newunivers-sdb/nu-browser-use/`, UNC `\\192.168.0.136\sdb\...` — 하나의 share를 셸마다 다르게 볼 뿐). 누락 금지: `stage_to_nas.sh`가 `*_export`를 디스커버리로 스테이징하고, `COLLECTION-MANIFEST.json`이 무엇이 거기 있는지 기록한다. 둘 다 `tests/ci/test_staging_coverage.py`가 강제한다 — 스테이징 누락과 **기록 누락은 다른 실패**이며 각각 검사한다.
   - **G드라이브 동기화는 2026-08-14 은퇴.** 이전 판의 3단계(`NAS → G드라이브 개발팀\<NAME>`)는 더 이상 수행하지 않으며, 매니페스트의 `deploy_rule`이 그 결정을 담는다. 3단계를 수행한다는 `sync_all.ps1`은 저장소·NAS·`$HOME` 어디에도 없다.
   - 은퇴 이후에도 `_DO-NOT-SYNC-TO-DRIVE.md` 표시는 유지한다. 외부 클라우드 배포가 언젠가 재개될 때 **어느 디렉터리가 그 경계 밖인지는 그때 다시 판단할 문제가 아니라 이미 내려진 결정**이기 때문이다.

## 수집 범위 (허용)

| 분류 | 내용 | 예시 |
|---|---|---|
| 카탈로그 메타데이터 | 제목, 장르/테마, 화수, 등급, 언어, 방영일 | Vigloo programs.json, ReelShort books.json |
| Engagement 지표 | viewCount, likeCount, bookmarkCount, read_count + 시점별 스냅샷/델타 | Vigloo `?episode=1` 페이지 스냅샷 |
| 홍보 에셋 | 포스터, 타이틀 이미지, 확장 썸네일 (CDN 무토큰 공개) | Vigloo assets 609장, ReelShort posters 602장 |
| 에피소드 스틸컷 | 플레이어가 공개 제공하는 썸네인 이미지 | Vigloo episode_thumbs 10,657장 |
| 참조 메타데이터 | DP 크레딧, 렌즈/조명/컬러 태그, 팔레트 | ShotDeck 150샷 |

## 수집 금지

- **에피소드 영상 원문** — HLS 스트림 세그먼트, 다운로드 파일 전부. 상업 콘텐츠 전체 복제는 원칙 1 위반이자 저작권 침해.
- **접근통제 우회** — 앱 전용 API 역설계, 재생 토큰 위조, 서명 체인을 보호장치 해제 목적으로 사용. (ReelShort 서명 재현은 웹이 익명 방문자에게 주는 카탈로그 읽기에 한해서만 사용한다.)
- **AI봇 명시 차단 소스 직접 스크래핑** — PromptHero, SimplyScripts, TV Tropes 등 ToS 리스크 명시 소스.
- **authwall 뒤 소셜 채널** — LinkedIn/TikTok/Instagram/Facebook/Linktree. robots가 자동화를 문장으로 금지하거나(LinkedIn·Facebook), `User-agent: *`에 `Disallow: /`이거나(Linktree), AI 크롤러를 지목 차단한다(TikTok). 채널의 **존재와 소유관계는 레지스트리에 기록하되 요청하지 않는다** — `promotion_channels.yaml`의 `access_tier: T2` + `collect: false`.
- **봇 방어 우회** — WAF 챌린지(예: col.com Alibaba Tengine 405), 레이트리밋 회피, UA 위장. 정상 브라우저 헤더(Accept 등) 전송은 우회가 아니라 정직한 클라이언트 동작이며, User-Agent는 계속 우리를 밝힌다.
- **암호화된 응답 봉투 해제** — 사이트가 SSR 페이로드를 대칭 암호화해 가린 경우(예: ShortMax `__NUXT_DATA__`), JS 번들에서 키를 복구해 푸는 것은 접근통제 우회다. **ReelShort 예외는 그 사이트의 익명 카탈로그 읽기로 한정된 것이지 일반 면허가 아니다.** 대체 경로: 브라우저는 정상 동작으로 이걸 복호화하므로 **렌더된 화면을 읽는다** — 방문자가 보는 것과 동일하고 봉투는 건드리지 않는다.

## 권리보호·침해 유통 관측 (2026-08-15 추가)

이 정책은 원래 홍보 채널과 카탈로그 소스만 다뤘고, 불법 유통 사이트를 향한 수집에는
**규칙이 없었다.** `newtoki_watch.py`(권리보호)와 `newtoki_market_intel.py` /
`newtoki_work_meta.py`(공급 측 관측)는 그 공백에서 일주일간 미결 상태로 남아 있었다.
공백은 허가도 금지도 아니므로 여기서 정한다.

**두 개의 서로 다른 목적**

| 목적 | 도구 | 질의 대상 |
|---|---|---|
| 권리보호 | `newtoki_watch.py` | **우리 작품 제목만.** 워치리스트 밖의 질의는 하지 않는다 |
| 공급 관측 | `newtoki_market_intel.py`, `newtoki_work_meta.py` | 목록 전수. 무엇이 유통되는지가 질문이므로 |

두 번째는 첫 번째의 가드레일 위반이 아니라 **다른 위임**이다. MUSO 계열 안티파이러시
업계가 하는 표준 관측이며, 사용자 요청(2026-08-14)에 근거한다. 다만 아래 바닥선은
목적과 무관하게 공통이다.

**허용 — 유통 사실**

제목, 사이트 내부 id, 섹션, 목록 위치, 카테고리별 총량, 갱신 시각, 작가·장르·원 플랫폼
귀속, 사이트 자체 `og:description` 시놉시스(**200자 이내**). 이것들은 표현이 아니라
유통에 관한 사실이며, 어느 서점 페이지에나 있는 종류의 정보다.

**금지 — 예외 없음**

에피소드 페이지, 에피소드 이미지·본문, 미디어 URL, 다운로드 파일. **에피소드 파일 자체가
침해물이므로 이를 복제하면 우리가 침해의 당사자가 된다.** 권리보호 목적이라도 마찬가지다.
증거는 건수·날짜·URL이지 사본이 아니다.

**robots**

불법 사이트라도 robots.txt는 확인한다. newtoki1.org는 `Allow: /`에 `/api/`, `/search`,
`/recent`, `/favorites` 등을 금지하며, 세 도구가 만드는 URL은 전부 `/<section>` + 쿼리라
준수 상태다 — 다만 2026-08-15까지 **아무도 확인하지 않아 우연히 준수하고 있었다.**
`visit()`이 이제 요청 전 검증하고 `RobotsRefusal`을 던진다. 거부를 빈 결과로 반환하지
않는 이유는 이 모듈이 대조 질의를 두는 이유와 같다 — 침묵을 안전으로 읽는 것이 최악의
실패다.

**배포 범위 — NAS 까지, G드라이브로는 보내지 않는다 (2026-08-16 결정)**

당시 원칙 4는 NAS → G드라이브 배포를 요구했고, 유통 인벤토리는 그 예외로 정해졌다. 2026-08-14에
G드라이브 동기화 자체가 은퇴하면서 이 예외는 실효적으로 무의미해졌지만 **표시는 남긴다** — 아래
판단은 배포가 재개될 경우에도 그대로 유효하다. 레코드가
`id + title`이고 사이트 URL이 `<host>/<section>/<id>`이므로 이 데이터셋은 **해석 가능한
침해물 색인**이기도 하다. 사내 저장소에 두고 분석하는 것은 관측이고, 외부 클라우드로
동기화하는 것은 배포에 가깝다.

- **2단계(로컬 → NAS): 한다.** `stage_to_nas.sh`가 `newtoki_market`을 포함하므로 NAS 사본이
  최신으로 유지된다.
- **3단계(NAS → G드라이브): 하지 않는다.** 디렉터리 안의 `_DO-NOT-SYNC-TO-DRIVE.md`가
  그 경계를 표시한다.

**이 제외는 코드로 강제되지 않는다.** 3단계를 수행한다는 `sync_all.ps1`을 저장소·NAS·`$HOME`
어디에서도 찾지 못했으므로, 여기 있는 어떤 스크립트도 3단계를 대신 거부할 수 없다. 표시 파일이
유일한 기제이며, 그것이 사라지지 않도록 `tests/ci/test_staging_coverage.py`의
`NO_DRIVE_SYNC`가 존재를 검사한다. NAS → G드라이브 동기화를 돌리는 쪽에서 이 디렉터리를
대상에서 빼야 한다.

## 지정 URL 참조 영상 (2026-08-18 추가)

원칙 1은 원문 저작물을 보관하지 않는다고 말하고, 「수집 금지」는 에피소드 영상 원문과
다운로드 파일 전부를 금지한다. 그 조항들이 겨냥한 것은 **플랫폼 카탈로그의 체계적 복제** —
숏드라마 플랫폼 영상을 훑어 코퍼스를 만드는 행위다. 운영자가 URL을 하나씩 지정한
개별 영상을 연출 레퍼런스로 받아두는 것에는 **규칙이 없었다.** 공백은 허가도 금지도
아니므로 여기서 정한다.

**허용 — 조건 전부를 만족할 때만**

| 조건 | 내용 |
|---|---|
| 지정성 | 운영자가 URL을 명시한 건에 한한다. 프로필 순회·피드 열거·검색·해시태그 수집 금지 |
| 익명성 | 익명 방문자가 받는 것과 동일한 경로. 로그인 세션 보유 시 **실행 중단**(요청 회피가 아니라 assert) |
| 유한성 | 목록은 사람이 만든다. 발견된 링크를 따라 목록이 자라면 그건 순회지 지정이 아니다 |
| 배포 정지 | NAS 까지. G드라이브로 보내지 않으며 `_DO-NOT-SYNC-TO-DRIVE.md` 로 표시한다 |

**왜 예외로 두는가**

연출 인텔리전스(`docs/video-corpus-sources.md` 의 목적)는 프레이밍·컷·리듬을 봐야 하고,
그건 메타데이터로 대체되지 않는다. 12건을 손으로 골라 참조하는 것과 플랫폼 하나를
통째로 미러링하는 것은 규모가 아니라 **성격이 다르다** — 전자는 사람이 볼 수 있는 것을
사람이 지정해 받아두는 것이고, 후자는 카탈로그를 복제해 대체재를 만드는 것이다.

**바닥선 — 예외 없음**

- 라이선스가 확인되지 않은 영상은 **내부 참조 전용**. 재배포·재가공물 공개·학습 데이터 편입 금지
- 상업 플랫폼(숏드라마 등) 카탈로그 영상은 **여전히 금지**. 이 절은 그 문을 열지 않는다
- 공개 라이선스 코퍼스(Apache-2.0/CC-BY 등)는 이 제한을 받지 않는다 — 라이선스가 배포를 허용하므로

**적용 현황**: `instagram_post_collect.py` → `~/instagram_export` (2026-08-18, 12건).
`tests/ci/test_staging_coverage.py` 의 `NO_DRIVE_SYNC` 가 표시 파일의 존재를 강제한다.

## 판단 기준: 라이브러리 vs 브라우저

robots.txt가 `User-agent: *` 그룹 없이 **스크래핑 라이브러리를 이름으로 차단**하는 경우
(예: flextv.cc가 `python-requests`/`Scrapy`/`wget`/`HTTrack`/`crawler4j`/`libwww-perl`을
열거하고 검색엔진만 화이트리스트), 형식적으로 우리를 구속하는 규칙은 없다(stdlib
`can_fetch('*')`는 True). 그러나 그 열거는 어떤 접근이 환영받지 못하는지 분명히 말한다.

이 경우 긋는 선은 **허용/금지가 아니라 라이브러리/브라우저**다. HTTP 경로가 더 쉽더라도
쓰지 않고, 실제 브라우저로 일반 방문자처럼 방문한다. 서버 동작도 같은 신호를 준다 —
flextv.cc는 기본 aiohttp 요청에 `400 Too many headers received`, 브라우저에는 정상 응답.

## 영상 데이터가 필요할 때의 합법 경로

1. **플랫폼 제휴/라이선스 계약** — 사업 개발 담당자 경유. 엔지니어링 경유 아님.
2. **공개 라이선스 코퍼스** — Wan2.2(Apache-2.0), LTX-Video(OpenRAIL-M), VideoFeedback(Apache-2.0), MultiCamVideo/ReCamMaster(Apache-2.0) 등 검증 완료 목록은 프로젝트 메모리 참조.
3. **자체 제작** — 생성 → NU Signal(시청자 행동) 수집 폐쇄루프.

## 접근 등급 (access_tier)

홍보채널처럼 "가치는 높은데 수집은 불가"가 섞인 소스군은 등급을 붙여 관리한다.
정의와 채널별 판정은 `scripts/site_collectors/registry/promotion_channels.yaml`,
근거는 `docs/promotion-intelligence-plan.md`.

- **T0** 무인증 HTTP + robots 클린 + 구조화 데이터 → 수집
- **T1** 도달은 되나 JS 렌더 → CDP 필요
- **T2** authwall 또는 robots 금지 → **등록만, 요청 안 함**

T2를 목록에서 지우지 않는 이유: 채널 소유관계는 그 자체로 인텔리전스이고, 정책·제휴
상황이 바뀌면 그대로 활성화된다. 금지는 문서상 약속이 아니라 `promo_registry_verify.py`가
기계적으로 강제한다(`collect: false`인 URL은 아예 요청하지 않음).

robots 판정은 **두 질문을 분리**한다 — `star`(일반 크롤러 규칙, 우리를 구속)와
`ai_named_disallow`(호스트가 AI 크롤러를 지목 차단했는가). 전자만 허용이고 후자가 참인
경우는 자동 판정하지 않고 `decision_pending: true`로 사람 판단까지 잠근다.

## 스냅샷·증분 운영

- 모든 콜렉터는 재실행 시 캐시 스킵으로 증분 수집.
- Engagement 스냅샷(`vigloo_snapshot.py`)은 실행일 기준 `snapshots/YYYY-MM-DD.json`으로 저장, 이전 스냅샷 대비 델타 자동 계산.
